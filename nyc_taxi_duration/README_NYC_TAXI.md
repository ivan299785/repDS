# Предсказание длительности поездок такси в Нью-Йорке

Проект по машинному обучению: регрессия для прогнозирования времени
поездки такси на основе геоданных, временных признаков и погоды.

## О проекте

**Бизнес-задача:** прогнозировать длительность поездок такси в Нью-Йорке
для автоматизации расчёта стоимости и оптимизации работы таксопарков.

**Техническая задача:** регрессия — предсказать `trip_duration` (секунды)
по характеристикам клиента, времени, географии и погодным условиям.

## Данные

| Источник | Файл | Содержание |
|---|---|---|
| Основные данные | `train.csv` | 1.5M+ поездок: id, vendor_id, время, координаты, passenger_count, trip_duration |
| Погода | `weather_data.csv` | Температура, видимость, ветер, осадки, явления по часам |
| Праздники | `holiday_data.csv` | Даты праздничных дней |
| OSRM API | `osrm_data_train.csv` | Расстояние, время в пути, число шагов по маршруту |

**Целевая переменная:** `trip_duration` — длительность поездки в секундах.

## Этапы работы

### 1. Подготовка данных
Объединены 4 источника. Обработаны пропуски: медиана по дате для погоды,
общая медиана для OSRM, `'None'` для погодных явлений.

### 2. Feature Engineering
**Временные:** `pickup_date`, `pickup_hour`, `pickup_day_of_week`, `pickup_holiday`.

**Географические:** `haversine_distance`, `direction`, `geo_cluster` (KMeans, 10 кластеров).

**Дополнительно:** `total_distance`, `total_travel_time`, `number_of_steps` из OSRM.

### 3. Очистка данных
- Удалены поездки >24 часов (4 записи).
- Удалены «телепортации» со скоростью >300 км/ч (407 записей).
- Логарифмирование: `trip_duration_log = log(trip_duration + 1)`.

### 4. EDA
- Распределение целевой переменной.
- Тест Д'Агостино: `trip_duration_log` не является нормальным (p < 0.05).
- Анализ «час × день недели» (heatmap), геокластеры, влияние погоды.

### 5. Моделирование
- Linear / Ridge / Lasso / Elastic Net.
- Random Forest, Gradient Boosting, XGBoost, LightGBM.
- 5-fold CV, 80/20 split, GridSearchCV, метрика RMSLE.

## Результаты

**Лучшая модель:** Gradient Boosting.

| Метрика | Train | Validation |
|---|---|---|
| **RMSLE** | 0.37 | 0.39 |

### Топ-3 признака
1. `total_distance`
2. `total_travel_time`
3. `pickup_hour`

### Основные выводы
- Гео- и OSRM-признаки дают наибольший вклад в качество модели.
- Логарифмирование стабилизирует распределение и соответствует RMSLE.
- Временные и погодные признаки добавляют полезный сигнал.
- Очистка выбросов заметно улучшает обучение.
